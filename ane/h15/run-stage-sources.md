# ane_h15 stages 4 and 5: where each claim comes from

Every register, address and sequence below carries its source, pinned to a commit or a file hash, and says whether it is an H15 observation or an inference from another generation. Nothing in stage 4 or 5 has run on hardware.

## H15 observations (T6030, 16-inch J516S, macOS 14.7 / firmware 27.0)
- Stage 0, 1 and 2 results: PR 175 on joshuaswarren/omarchy-ane, comment of 2026-10-23T01:57Z (Chris Kearney). CPU_STATUS 0x0030002a, RVBAR_LO 0x1, RVBAR_HI 0x100, MBOX_A2I_CTRL and MBOX_I2A_CTRL 0x20001, five pmgr words ACTUAL=0xf, ANE DART nodes disabled. This is the only H15 register measurement. It is the source of `rvbar_expect` and of the preflight values.
- DART window addresses (0x309800000, 0x309810000, 0x309820000, 0x309804000, 0x4000 each) and `dart,t8110`: macOS 27.0 ADT facts in `data/ane-soc/t6030.json` (source S1 there, receipt sha256 04fe38b8…ffdb84). Not measured on silicon by us. The names `ttbr0..3` in that file are the summary's, not roles from the ADT.

## Inference from another generation (not measured on H15)
- STOPPED is the "started" flag, bit 1 of CPU_STATUS; RUN is CPU_CONTROL bit 4: m1n1 `proxyclient/m1n1/hw/asc.py` at 97820568035b8d7035c68e4126f203d86c76abe4, lines 12-24 (`R_CPU_CONTROL.RUN = 4`, `R_CPU_STATUS.STOPPED = 1`, `RUNNING = 0`) and 77-85 (`is_running()` is `not STOPPED`, `boot()` is `CPU_CONTROL.set(RUN=1)`, `shutdown()` is `set(RUN=0)`). Observed on the M6: the RUN write took CPU_STATUS 0xa to 0x8 (STOPPED cleared, RUNNING never read 1), w7H boot 235c8ff4, log `dmesg-w7h-ane-v7.txt` sha256 74e9b666c3d03b8f07997e33253ea9734b1886999061d801f196ddc8d14bb48b.
- Start and stop sequence (read CPU_CONTROL, OR 0x10, write; stop: clear bit 4, write, re-read, clear bit 5, write): macOS 27.0 `AppleASCWrapV8::_runCPU` as decoded from the T8152 kernelcache (sha256 09746d1f442153956ba00b385f49bc245460c1ebea92cae7e9e0e4f240745b85) in `w74-t8152-ane-mailbox-dart.md` (sha256 d383f6741bf98b1a8140a72c1dde38e333d19f9d87c91334b8f21068e84f5857). That is the M6's ascwrap-v8. The H15 ANE is `iop,ascwrap-v6`. That the same bit 5 step applies on H15 is an inference. m1n1 clears only bit 4.
- Reading CPU_CONTROL: `ane_h15_read_ok()` keeps it off the stage 2 allowlist ("hostile on T6001", from the T6021 work, `ane/t6021/ane_t6021.h` at 16cfa8720b80677dbcdf8fd1d04077a8b72768bf). Stage 5 reads it once, in a dedicated function, before any write, because the macOS sequence is a read-modify-write and a blind write could clear bit 5. No H15 read of it exists. A fault here happens before anything is written.
- Mailbox registers: CTRL words at wrapper + 0x110 and + 0x114 (read on T6030 in PR 175). Receive registers I2A_RECV0 at + 0x830 and I2A_RECV1 at + 0x838, 64-bit, pop on read: `ane/t6021/ane_t6021.h` at 16cfa8720b80677dbcdf8fd1d04077a8b72768bf lines 138-147 (T6021, observed there), `drivers/soc/apple/mailbox.c` in omarchy-linux at 57f8f6deaa3a5ee97d820dc97844bf448e4d7fed lines 39-47 and 405-430 (`APPLE_ASC_MBOX_I2A_RECV0 0x830`, the v4 layout the other T6030 ASCs use). Not read on H15; stage 5 reads them only if I2A leaves EMPTY.
- DART registers (PARAMS3 +0x08, PARAMS4 +0x0c, PROTECT +0x200, PROTECT_LOCK +0x208, ENABLE_STREAMS +0xc00, TCR +0x1000 + 4*sid, TTBR +0x1400 + 4*sid, one TTBR per stream, up to 256 streams): `drivers/iommu/apple-dart.c` in omarchy-linux at 94fb23346d522edf53722357c426a3e58030beea, lines 91-148 and the t8110 hw table (`ttbr_count = 1`, `max_sid_count = 256`). Stage 4 reads 64 streams. Not read on H15.
- Why a DART scan comes before a core start: w7C's offline RE of the M6 ANE DART (`~/.local/share/apple-silicon-lab/entries/w7c/20261023T2347Z-omp-studio-local-m6-ane-dart-re.md`, sha256 of the report not recorded here): macOS programs TEXT and DATA mappings and enables the stream before RUN. On the M6 the ANE DART was never read, so whether iBoot leaves a stream enabled is unmeasured (w7C U1, w7H "not tested"). Stage 4 measures that on H15.

## What the stages can and cannot show
- Stage 4: whether a stream is enabled and translating, which stream, and whether the block is locked. Not that the mapping covers the firmware, nor that the core would run.
- Stage 5: whether the core leaves STOPPED, whether it posts a message, and whether it stops again. With no mapped DART, silence is the expected result and does not mean the core is broken.
